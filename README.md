# Znanium.ru downloader (векторный PDF из страниц читалки)
## Идейный предшественник — [znanium-savebooks](https://github.com/luxname/znanium-savebooks "znanium-savebooks")

Переписан на Rust. Разрабатывается и проверяется на Windows; сборки для Linux и
macOS собираются в CI, но не тестировались.

Скачивает купленные книги с сайта [znanium](https://znanium.ru/) и складывает их
в **векторный** PDF — текст остаётся кривыми Безье из исходного SVG, а не
растровой картинкой, как в предыдущей версии.

## Как пользоваться

1. Нужен аккаунт с купленной книгой.
2. Рядом с исполняемым файлом создать `links.txt` и добавить в него ссылки на
   книги — по одной на строку:

   ```
   https://znanium.ru/read?id=84127
   https://znanium.ru/read?id=489683
   ```

3. Запустить, передав логин и пароль:

   ```bash
   salvis login password
   ```

   Первый аргумент — **логин** от учётной записи, второй — **пароль**.
   Необязательный флаг `--headless` прячет окно Firefox.

Готовый бинарник можно взять во вкладке Releases (Linux x86_64, Windows x86_64,
macOS aarch64) либо собрать самому:

```bash
cargo build --release
```

Firefox для Playwright программа доустанавливает сама при первом запуске.

## Что появляется на диске

| Путь | Что это |
| --- | --- |
| `links.txt` | Список ссылок на книги (создаёте вы) |
| `cookies.json` | Сохранённая сессия; создаётся при первом входе и переиспользуется, пока не протухнет |
| `All-Books/<название>.pdf` | Собранная книга целиком |
| `Pages/(84127) <название>/page_0001.pdf` | Та же страница отдельным файлом |
| `Pages/(84127) <название>/page_0001.svg` | Исходный SVG страницы — из него книга пересобирается |
| `Pages/(84127) <название>/book.json` | Ссылка, название и число страниц |

Каталог книги назван по id из ссылки, а не только по заголовку: одноимённые
издания не затирают друг друга, а переименование книги на сайте не приводит к
повторной выкачке.

## Докачка

Страницы ложатся на диск сразу по мере загрузки, поэтому запуск можно прервать в
любой момент. При следующем запуске программа сверяет, каких страниц не хватает,
и докачивает только их:

* страница считается готовой, когда на месте оба файла — `.pdf` и `.svg`;
* если не хватает части страниц — открывается читалка и доливаются пропуски,
  после чего книга пересобирается целиком;
* если на месте всё и книга уже собрана — ссылка пропускается, браузер для неё
  не открывается вовсе.

Отсюда и `.svg` рядом с каждой страницей: книгу нужно уметь собрать из того, что
лежит на диске, а не только из того, что скачано в текущем запуске.

Если после прогона в логе осталось «в книгу вошло N страниц из M» — просто
запустите программу ещё раз, недостающее доберётся.

## Как это устроено

Сырой ответ XHR `/read/page` отдаёт намеренно повреждённые данные: картинка
меняется при повторном запросе одной и той же страницы, а 97–98% ссылок `<use>`
не находят своих `<defs>`. Парсить его бесполезно. Зато JS читалки сам
расшифровывает эти данные и вставляет корректный `<svg>` в DOM, в
`#bookreadcont{N}` — оттуда мы результат и забираем.

Две неочевидные вещи, на которых держится корректность вывода:

* **Глифы шрифтов лежат за пределами `<svg>` страницы.** В браузере
  `<use xlink:href="#font_1_1_1">` разрешается по всему документу, поэтому на
  экране всё правильно. Но в вырезанном `el.outerHTML` такие ссылки повисают: на
  реальной странице это 201 уникальная ссылка против ровно одного `id` внутри
  файла — весь набранный этими глифами текст пропадал, оставались только фигуры,
  нарисованные прямо в потоке. Поэтому перед выгрузкой ссылки обходятся
  транзитивно (`href` и `url(#…)`), а найденные определения вклеиваются в
  `<defs>` клона.
* **`printpdf::Svg::parse` не подходит для этой задачи.** Он прогоняет SVG через
  svg2pdf, а затем пересобирает результат в свой XObject, записывая в
  `/Resources` только ColorSpace — все вложенные Form XObject'ы (группы с
  clip-path, маской, прозрачностью), ExtGState, Shading и Pattern теряют имена и
  не рисуются. Он же жёстко задаёт svg2pdf `dpi = 300`, отчего содержимое выходит
  размером 0.24 от натурального. Поэтому PDF собирается напрямую через
  `svg2pdf::to_chunk` + `pdf-writer`, а usvg работает с `dpi = 72`, чтобы единица
  SVG равнялась точке PDF.

Небольшой остаток намеренно испорченных читалкой ссылок (единицы на страницу)
восстановить нельзя — их нет нигде в документе. О таких страницах программа
предупреждает в консоли.
